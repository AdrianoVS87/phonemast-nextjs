## 1. Legacy domain: phonemastcompany.co.uk

**What happens today (tested 24 Nov 2026):**

- Every path on every host answers **301**, not the 302 the audit reported.
- The redirect goes to `http://phonemastadvice.co.uk/`, so it takes four hops to reach the site:
  `http://www.phonemastcompany.co.uk/contact/` → `https://www.phonemastcompany.co.uk/contact/` →
  `http://phonemastadvice.co.uk/` → `https://phonemastadvice.co.uk/` → `https://www.phonemastadvice.co.uk/`.
- Every old page lands on the homepage.

**Where it is configured:** not in this repo or on Vercel. The domain resolves to `185.151.30.171`, an Apache
server on shared hosting. The redirect is that host's `.htaccess`, or a "redirect" setting in its control
panel.

**What to set:**

1. Remove any existing domain-wide redirect in that hosting control panel.
2. Replace the `.htaccess` at the web root of `phonemastcompany.co.uk` with the rules below. They are
   generated from `src/seo/redirects.ts` by `node scripts/generate-legacy-htaccess.mjs`, and the old paths
   come from the Wayback Machine index of the old site.
3. Each rule is one 301 hop straight to the final `https://www.` URL. Paths with an equivalent go there;
   anything unmapped goes to the homepage; injected spam (`/ihao/...`) answers 410.

If the HTTPS certificate on `phonemastcompany.co.uk` lapses, HTTPS requests fail before any redirect.
Keep it renewed for as long as the domain has links pointing at it.

## 2. Bare domain over HTTP

`http://phonemastadvice.co.uk/` takes two hops (Vercel upgrades to HTTPS first, then sends the bare domain
to `www`). Every other variant is one hop, and the proxy handles bare-domain paths in one. To remove the
remaining hop, the domain can be submitted to the HSTS preload list, after which browsers never make the
HTTP request. Preloading is hard to undo and covers every subdomain, so it needs the owner's decision. It
is not done here.
